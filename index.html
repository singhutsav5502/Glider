Keep your tokenson the ground

Glider sits between your AI coding CLI and its backend. The turns that do not need a frontier model — renames, explanations, formatting — land on your own machine. The rest carries on to the cloud, and your CLI never knows the difference.

Three things it does

Named for what you do with them, not for the subsystem underneath.

Hand a task to another CLI

Type the target at the end of a message and stay where you are. If that CLI stops to ask permission, the question comes back to you — answer it, and the run picks up where it stopped.

refactor this module /agy

Send the cheap turns local

A rule ladder decides each request: explicit commands first, then a task classifier, then your own Starlark, then a token ceiling. You can always override it by hand.

/local explain this function

See why it chose that

Every intercepted request shows up in a local dashboard with the rule that claimed it and the reason. No decision is a black box.

3 000 ft

Two ways in

You do not have to choose up front. Start with the gateway; switch later if a CLI ignores proxy settings.

Gateway

Point the CLI at Glider with one environment variable or base-URL setting. Explicit, easy to reason about, works with every CLI.

http://127.0.0.1:8080/v1

Transparent

Glider redirects the CLI's outbound HTTPS at the OS level. Nothing to configure, and it works on a session that is already open.

Needs Administrator on Windows or root on Linux, and it matches by process name across the whole machine. Read how interception works before you turn it on.

The ladder

Rules are read from the top. The first one that matches sets the route. This is the default profile, shipped as it stands.

A delegate flag is claimed before any of this runs, so handing work to another CLI never collides with routing. The full ladder.

Land it

Pure local mode. No cloud key needed, and nothing leaves the machine. 

# 1 — a local model
ollama serve
ollama pull qwen2.5-coder:14b

# 2 — Glider
.\glider.exe --config configs\glider.local.yaml

# dashboard  http://127.0.0.1:8081
# gateway    http://127.0.0.1:8080/v1

Then point your CLI at the gateway — or turn on transparent mode and skip that step. The full walkthrough.
