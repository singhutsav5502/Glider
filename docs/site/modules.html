api

Path A surface. Parses chat completions and Responses bodies into backend.CompletionRequest, calls Completer.Complete, writes SSE or JSON. Anthropic Messages-shaped requests are normalized to OpenAI tool/message layout. Does not own routing policy — that is entirely the orchestrator + router.

orchestrator

Heart of the harness. PipelineCompleter is the single completion entry used by both gateway and MITM. Surrounding pieces:

  • SimpleExecutor / FallbackChain — health, breaker, warm, rate limit, cloud fallback
  • PriorityQueue — optional enqueue before execute
  • FanOutExecutor — multi-backend fan-out, flag-gated (off by default)
  • ModelLifecycle / VRAM adapter — EnsureWarm / unload
  • ErrOriginPassthrough — MITM signal only

router

Engine.Route: explicit hard override, then first matching rule by priority. Built from yaml via NewEngineFromConfig, which also injects task classifier and optional complexity rules. Starlark scripts run in a sandboxed executor. Tool followup and composer wrap-up are first-class rule types — see Routing.

mitm

CONNECT accept loop, CA leaf minting, host allowlist, blind tunnel vs decrypt, HTTP intercept classification, StreamChat* legacy fulfill, Bidi/RunSSE fulfill hub, sticky turn family, debug RPC dumps when debug_agent_rpc is on. Policy flags: agent_rpc_fulfill, origin_on_local_error, agent_rpc_canned_on_error (R&D only).

cursorrpc

Wire-format layer for Cursor Agent RPC: BidiAppend body scan/extract, TipTap text, RunSSE frame encode/decode, helpers like IsRootAgentRunSSE. Keeps protobuf / Connect details out of the orchestrator. Path B text-only local fulfill depends on the text codec; opt-in agent_rpc_tool_codec ships a common ToolCall wire map (full catalog DEFERRED).

contextgraph & contextkit

contextgraph is the source of truth for route/sticky analytics — append events, index by turn/request/session, answer “is cloud family still live?”. contextkit holds compact episode summaries for local prompt injection. Locals must not receive raw TipTap mega-dumps; bounded transform owns that contract (Context).

vendors & ngl

vendors: CLI discovery (configs/vendor_candidates.yaml), per-vendor CommandTemplates, headless exec (RunWithOptions), denial detection and the permission-relay resume loop (ResolveDelegate, RegisterPendingResume), and per-PID workspace-directory scoping (WorkspaceStore) — all behind a VendorAdapter interface so no vendor name is ever branched on in shared code. ngl (Native Glider Language) is the wire-format half of the same boundary: a canonical Turn/Part/EditViews envelope each vendor's adapter translates into and out of, so a delegated edit renders as a normal diff regardless of which CLI produced it. See adapter_boundary.md and permission_relay_design.md.

config, metrics, vram, backend, transform, dashboard, hotswap, tray

  • config — single schema for all profiles; validate catches bad priorities / MITM hosts.
  • metrics — LOCAL/CLOUD/CANNED distribution, MITM action tags, history for dashboard charts.
  • vram — nvidia-smi monitor, hybrid allocation, headroom and idle unload.
  • backend — pluggable Complete stream; cloud providers share OpenAI/Anthropic clients.
  • transform — estimate tokens; BoundLocalContext; optional rewrite pipeline (off by default).
  • dashboard — Overview, VRAM & Models, Rules Engine, Config, Vendors, MCP, Workspace; serves this docs site when present.
  • hotswap — named module registry (fan_out, backends, classifier) bound to config.Provider.Watch.
  • tray — system tray icon + Exit (Windows only; no-op elsewhere).
