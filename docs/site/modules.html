api

Path A surface. Parses chat completions and Responses bodies into backend.CompletionRequest, calls Completer.Complete, writes SSE or JSON. Anthropic Messages-shaped requests are normalized to OpenAI tool/message layout. Does not own routing policy — that is entirely the orchestrator + router.

orchestrator

Heart of the harness. PipelineCompleter is the single completion entry used by gateway, MITM, and loops. Surrounding pieces:

  • SimpleExecutor / FallbackChain — health, breaker, warm, rate limit, cloud fallback
  • PriorityQueue — optional enqueue before execute
  • FanOutExecutor — multi-backend fan-out (partial productization)
  • ModelLifecycle / VRAM adapter — EnsureWarm / unload
  • ErrOriginPassthrough — MITM signal only

router

Engine.Route: explicit hard override, then first matching rule by priority. Built from yaml via NewEngineFromConfig, which also injects task classifier and optional complexity rules. Starlark scripts run in a sandboxed executor. Tool followup and composer wrap-up are first-class rule types — see Routing.

mitm

CONNECT accept loop, CA leaf minting, host allowlist, blind tunnel vs decrypt, HTTP intercept classification, StreamChat* legacy fulfill, Bidi/RunSSE fulfill hub, sticky turn family, debug RPC dumps when debug_agent_rpc is on. Policy flags: agent_rpc_fulfill, origin_on_local_error, agent_rpc_canned_on_error (R&D only).

cursorrpc

Wire-format layer for Cursor Agent RPC: BidiAppend body scan/extract, TipTap text, RunSSE frame encode/decode, helpers like IsRootAgentRunSSE. Keeps protobuf / Connect details out of the orchestrator. Path B text-only local fulfill depends on the text codec; tool codec availability gates any future local tool-loop fulfill.

contextgraph & contextkit

contextgraph is the source of truth for route/sticky analytics — append events, index by turn/request/session, answer “is cloud family still live?”. contextkit holds compact episode summaries for prompt injection and swarm merge. Locals must not receive raw TipTap mega-dumps; bounded transform owns that contract (Context).

loop & swarm

loop: hoop CRUD, runner lifecycle, stage prompts, critic SCORE parse, persistence under ~/.glider/loops/. swarm: worker fan-out, merge, dashboard runner, and the hot-swap Registry that applies config Watch to named modules (including loop stages). Operator docs: Loop Engineering, deep dive hot-swap.

config, metrics, vram, backend, transform, dashboard

  • config — single schema for all profiles; validate catches bad priorities / MITM hosts.
  • metrics — LOCAL/CLOUD/CANNED distribution, MITM action tags, history for dashboard charts.
  • vram — nvidia-smi monitor, hybrid allocation, headroom and idle unload.
  • backend — pluggable Complete stream; cloud providers share OpenAI/Anthropic clients.
  • transform — estimate tokens; BoundLocalContext; optional rewrite pipeline (off by default).
  • dashboard — Overview, VRAM, Rules, Config, Hoops & Swarm; serves this docs site when present.
