Step-by-step tech (process startup)

Grounded in cmd/glider/main.go:

  1. Load config + watcher config.LoadConfig · config.NewProvider · StartWatcher Defaults if load fails. Watch reloads rules/aliases/log without restart.
  2. Register backends + models backend.NewRegistry · ollama/vllm/cloud clients · RegisterModel Ping health; VRAM estimates from YAML models:.
  3. Build router + executor + pipeline router.NewEngineFromConfig · SimpleExecutor · FanOutExecutor · PipelineCompleter Atomic pointer for hot router swap. Optional fan-out / swarm registry.
  4. Wire context + metrics contextgraph.Store · contextkit.Store · metrics.Collector + HistoryStore Session id run-<uuid>; history under ~/.glider/history.
  5. Start Gateway api.Server.Start · listen server.proxy_port (8080) Handlers call Completer.Complete.
  6. Start MITM (if enabled) mitm.Proxy.Start · CA under ~/.glider/mitm · port 8082 Interceptor holds same harness; agent_rpc_fulfill arms the fulfill hub.
  7. Start Dashboard dashboard.Server.Start · port 8081 · Bus for live WS Config, VRAM, rules, hoops/swarm APIs (UI owned separately; do not restyle here).
  8. Await SIGINT/SIGTERM signal.Notify · graceful shutdown of listeners

Hot-reload vs restart

Hot (config.Provider.Watch / swarm.Registry): router rules, aliases, transform, log level, classifier, fan-out/swarm opts, hoop templates. Restart required: listen ports, MITM CA/hosts, backend client wiring, cloud provider keys at process start. Details: deep dive · hot-swap, concurrency.
