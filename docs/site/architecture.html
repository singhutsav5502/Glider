Core

Architecture

Glider is a shared harness: every completion (gateway or MITM) goes through resolve model alias → tokenize → route → transform → execute.

Model alias — rewrite the client’s model ID via model_aliases (e.g. Cursor’s gpt-4o → qwen2.5-coder:14b) before the router runs. Routing picks which model/backend answers one request. Delegation (see Tools & MCP and planning/permission_relay_design.md) instead hands a whole task to a different CLI vendor.

For Path A/B lifecycles, sticky cloud, fulfill hub, and failure modes, see the architecture deep dive, data-flow sequences, module map, and concurrency model.
