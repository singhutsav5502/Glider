Architecture

Glider sits beside whichever AI coding CLI you run — Claude Code, Cursor Agent, or Antigravity (agy) — as one Go process (cmd/glider) with three listen surfaces, a shared completion pipeline, and no code in that pipeline that branches on which CLI is talking.

The shared pipeline

Every completion — from the gateway or from MITM — goes through one orchestrator.PipelineCompleter. The only difference is CompleteOptions.OriginPassthrough: the gateway falls back to BYOK cloud on non-local, MITM tunnels back to the CLI's own origin instead. 

CompletionRequest
  → ApplyModelAlias           (model_aliases: e.g. gpt-4o → qwen2.5-coder:14b)
  → Tokenizer.EstimateRequestTokens
  → router.Engine.Route       (see routing.html for full priority order)
  → [origin gate — MITM only, non-local → ErrOriginPassthrough]
  → episodes + BoundLocalContext   (local only — never the full history)
  → Transformer.Apply         (opt-in, off by default)
  → Executor.Execute          (Ollama | vLLM | OpenAI | Anthropic; fallback chain, circuit breaker)
  → metrics + contextgraph events

A message with a /vendor flag (/claude, /cursor-agent, /agy) never reaches this pipeline at all — DelegateHandler claims it first. See Delegation.

Hot-reload vs. restart

Hot (config.Provider.Watch): routing rules, model aliases, transform config, log level, backend/model clients, hot-swap modules. Restart required: listen ports, MITM CA/hosts/transparent-interception settings.

Failure modes

Local fulfill error (hybrid)Default: fall back to origin (mitm.origin_on_local_error)
Pure localorigin_on_local_error: false — surface the error instead of a silent origin fallback

Concurrency notes

  • Hot-path config (Config, router.Engine) is swapped via atomic.Pointer — readers never block on a reload.
  • Gateway and MITM call PipelineCompleter.Handle concurrently; it's immutable wiring over synchronized dependencies — never stash per-request mutable state on it.
  • A delegate call's subprocess is tied to the incoming HTTP request's context — no background runner outlives the request.
  • Cursor's fulfill hub (AgentFulfillHub) guards its waiting/pending/family maps under one mutex — detail in MITM.

Config profiles

  • configs/glider.yaml — dual-mode default (gateway + MITM)
  • configs/glider.local.yaml — Ollama-only, no cloud fallback (Pure local)
  • configs/glider.cloud.yaml — cloud-leaning, MITM off
