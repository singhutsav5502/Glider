Tools

Tools & MCP

Glider unifies builtins and Model Context Protocol (MCP) servers under internal/tools. The registry dispatches tools: refs and feeds results into the model when the agentic tool loop is active. Full planning write-up: planning/tools.md.

Workspace, ScopeRel & artifacts

Default sandbox: ~/.glider/workspace. Each run gets:

runs/<run-id>/
  work/   ← clones, scratch
  out/    ← final reports

ScopeRel: with a run active, bare paths resolve under that run’s work/ (same for fs_* and git_clone):

audit-target  →  runs/clone-repo-security-audit/work/audit-target
tools:
  - { name: git_clone, kind: builtin }
  - { name: fs_list, kind: builtin }
  - { name: artifact_write, kind: builtin }
# artifact_write text input
out findings.md
# Severity: high
…

Dashboard → Workspace tab, or GET /api/workspace?run=<id>.

Blind pre-pass vs agent tool loop

PathWhat runs
Blind pre-passOnly safe tools (datetime, fs_list, git status/diff/log, MCP list) with input "." — never the task goal
Agent loopgit_clone, writes, search, web, MCP — via native tool_calls or parsed text JSON
{"name":"fs_list","arguments":{"input":"audit-target"}}

Undeclared tools are rejected. MCP "*" expands before CallTool. MaxSteps ≥ 20 (sequential) / ≥ 28 (parallel workers).

Web search

# configs/glider.yaml
orchestration:
  tools:
    web_search:
      provider: auto   # brave → tavily → serpapi → searxng → duckduckgo
      max_results: 5
# .env.local (optional keyed providers)
BRAVE_SEARCH_API_KEY=
TAVILY_API_KEY=
SERPAPI_KEY=
SEARXNG_URL=http://127.0.0.1:8080

Tools: web_search (snippets) and web_fetch (readable page). Both are agent-loop only (not blind-safe).

GitHub connect (Cursor-like UI)

Glider running is not the same as GitHub MCP connected. If the tools panel says Documented catalog, the dashboard is up but the MCP session to GitHub is not — sign in or Connect for source=live.

  1. Sign in with GitHub — device flow (enter a code at github.com/login/device). Put GLIDER_GITHUB_OAUTH_CLIENT_ID in .env.local (copy from .env.example; gitignored). Shell env still wins over the file.
  2. Paste PAT — saves to ~/.glider/credentials/github_token (0600) and connects HTTP github.
  3. Forget token — clears the credential file and disconnects.

GitHub token (env or credential file)

Never put a PAT in YAML. Prefer the MCP tab UI, or set one of these in the Glider process environment (first non-empty wins):

GITHUB_PERSONAL_ACCESS_TOKEN=ghp_...   # preferred
GITHUB_TOKEN=ghp_...
GH_TOKEN=ghp_...

Config validation rejects inline auth.token; use token_env only. At startup Glider also hydrates from ~/.glider/credentials/github_token when env is empty.

Dashboard MCP UI

  1. Open Dashboard → MCP tab (http://127.0.0.1:8081).
  2. Use Sign in with GitHub or Paste PAT, then confirm HTTP shows connected.
  3. Use Connect / Disconnect / Reconnect / Refresh on each server row.
  4. Tools list: live when the session is up; catalog is a static fallback with an explicit reason (not “server off”).
