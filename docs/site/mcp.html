Tools & MCP

internal/tools unifies builtins, plugins, and MCP servers under one registry, sandboxed to a workspace directory. It's built and tested, and the dashboard/delegation's edit-rendering path uses parts of it, but nothing currently drives its own agentic tool loop (RunAgentLoop) — that ran under the removed hoop/swarm stage runner. Today, multi-turn agent work happens by delegating to a real vendor CLI, which brings its own tool loop.

Workspace & sandbox

Default: ~/.glider/workspace (orchestration.tools.workspace — never set this to .).

runs/<run-id>/
  work/   ← clones, scratch, intermediate files
  out/    ← final deliverables

Bare paths resolve under the active run's work/ automatically (ScopeRel). Builtins cannot escape the workspace root.

MCP

GitHub is the built-in server (HTTP hosted Copilot MCP + Docker stdio); internal/mcp.Manager supports any additional stdio or Streamable-HTTP server.

Auth (never inline auth.token in config):

export GITHUB_PERSONAL_ACCESS_TOKEN=ghp_...   # or GITHUB_TOKEN / GH_TOKEN

Or Dashboard MCP tab → Sign in with GitHub (OAuth device flow) or Paste PAT (writes ~/.glider/credentials/github_token, mode 0600).

The Streamable HTTP client persists Mcp-Session-Id, sends MCP-Protocol-Version + X-MCP-Toolsets on follow-ups, and on a 401/403 clears the session and re-initializes once before retrying.

Dashboard MCP tab: server list, Connect/Disconnect/Reconnect/Refresh, live tool catalog (falls back to a documented catalog when nothing's connected). Full endpoint list: API · MCP.

Web search setup

# .env.local
BRAVE_SEARCH_API_KEY=
TAVILY_API_KEY=
SERPAPI_KEY=
SEARXNG_URL=http://127.0.0.1:8080

Provider auto tries each in order, falling back to DuckDuckGo HTML (no key). Forcing a keyed provider with an empty env returns a clear error instead of inventing results.
