Architecture deep dive

Glider is a Go local-first AI harness for Cursor. It is not a fork of Cursor and not a replacement IDE. It sits beside Cursor as a dual-mode proxy: an OpenAI-compatible gateway (Path A) and an HTTPS MITM forward proxy (Path B), both feeding one shared harness — orchestrator.PipelineCompleter — that runs resolve model alias → tokenize → route → transform → execute (model_aliases rewrites the client model ID before routing). Routing chooses the backend for one request; cross-CLI delegation (internal/vendors) instead hands an entire task to a different CLI vendor.

This page is the long-form companion to Architecture and the C4 model (C1-C4). Companion pages: Data flow, Modules, Concurrency. Authority for status: planning/README.md.

Surfaces & ports

cmd/glider/main.go constructs one PipelineCompleter, then attaches it to the gateway and MITM interceptor (delegation runs headless CLI subprocesses via internal/vendors, not a worker pool). Listen addresses come from config; defaults live in config.DefaultConfig() and configs/glider.yaml.

SurfaceConfigDefaultRole
Gateway server.proxy_port :8080 OpenAI-compatible /v1/*; Cursor Override Base URL (Path A)
Dashboard server.dashboard_port :8081 Operator UI, REST /api/*, WebSocket /ws, optional static docs at /docs/
MITM mitm.port :8082 HTTP CONNECT forward proxy; decrypt allowlisted Cursor Agent hosts (Path B)

│   Cursor   │────────────────────────────────▶│ Gateway (Path A) │──▶ Ollama / vLLM / BYOK

│            │────────────────────────────────▶│  MITM (Path B)  │──▶ Local text OR Cursor origin
└────────────┘                                  └─────────────────┘
                         Dashboard :8081 (metrics, rules, vendors)

MITM host allowlist (intro profile): api2.cursor.sh, api3.cursor.sh, api4.cursor.sh, *.api5.cursor.sh. Implemented by mitm.HostMatcher: exact match or *.suffix (also matches apex). Non-matching CONNECT targets get a blind tunnel (no decrypt). Matching hosts get a leaf cert minted by the Glider CA under ~/.glider/mitm/.

Hot-reload vs restart. config.Provider.Watch can refresh router rules, aliases, transform, log level, and hot-swap modules without restart. Changing listen ports, MITM CA/hosts, or backend clients requires a process restart.

Shared harness — PipelineCompleter

File: internal/orchestrator/pipeline.go. Both Path A and Path B call into the same type; the difference is CompleteOptions.OriginPassthrough.

EntryCallerBehavior
CompleteGatewayHandle with passthrough off — non-local runs BYOK cloud
CompleteLocalMITMNon-local → ErrOriginPassthrough (Cursor origin tunnel)
DecideLocalPath B BidiAppendAlias → tokenize → route only; arms fulfill hub

Handle stages (strict order)

  1. Alias — ApplyModelAlias; preserves Metadata.OriginalModel.
  2. Tokenize — Tokenizer.EstimateRequestTokens → Metadata.EstimatedTokens.
  3. Route — Router.Route; fill BackendName via ResolveBackendName (cloud→openai, else typically ollama); apply model/adapter.
  4. Emit — EventRouteDecided into contextgraph (if wired).
  5. Origin gate — MITM + non-local → metrics origin_passthrough, EventOriginPassthrough, return ErrOriginPassthrough.
  6. Episode inject (local only) — up to TransformCfg.LocalEpisodeCount compressed episodes from contextkit.Store.
  7. BoundLocalContext (local only) — policy latest_turn: keep system (capped) + latest user turn (+ trailing tool-loop msgs if present).
  8. Transformer — opt-in Transformer.Apply (default yaml has transform.enabled: false).
  9. Execute — Executor.Execute (queue, lifecycle warm, fallback chain, circuit breaker).
  10. Metrics wrap — buffered channel + goroutine drains chunks, records LOCAL/CLOUD, may EventFulfilledLocal and episode record.
StickyCloud / deny-local is enforced in MITM before CompleteLocal. The pipeline never overrides an ArmOrigin decision from the fulfill hub.

Path A lifecycle (gateway)

Cursor Override OpenAI Base URL → http://127.0.0.1:8080/v1. Prefer model IDs with a cus- / glider- prefix so Cursor does not hijack Agent traffic back to api2. Gateway routes (internal/api/server.go):

  • POST /v1/chat/completions — Chat / Ask; also Agent when BYOK-shaped
  • POST /v1/responses — Responses API; normalized into CompletionRequest
  • GET /v1/models, GET /healthz

Path A is the proven path for Agent + tools: full JSON body (including tools / tool_choice) enters the harness. Classifier tools_force_cloud (default true) sends tool-bearing turns to cloud unless every tool is allowlisted. Local backends that reject tools raise ToolsUnsupportedError and fall through the fallback chain to BYOK cloud when allowed. Anthropic-shaped bodies are normalized (internal/api/anthropic_normalize.go); SSE streams can emit tool_calls deltas.

Non-local on Path A means your OpenAI/Anthropic keys — not Cursor subscription origin. That is the essential difference from Path B.

Path B lifecycle (MITM Agent RPC)

Cursor http.proxy → http://127.0.0.1:8082, trust Glider CA, disable HTTP/2 for intercepted hosts. Flow: 

CONNECT host:443
  → 200 Connection Established
  → HostMatcher.Match?
       yes → TLS leaf + decrypt HTTP (mitmSession)
       no  → blindTunnel (bidirectional io.Copy)

Decrypted requests are classified (ClassifyPath): OpenAI-compat JSON on allowlisted hosts, Agent RPC (Connect/protobuf), Cursor control, or other. With mitm.agent_rpc_fulfill: true (intro default), Agent traffic uses the BidiAppend + RunSSE split observed in cursor-tap captures:

  1. BidiAppend — prompt/context envelope arrives; TipTap latest-turn text extracted (cursorrpc.ExtractBidiCompletionRequest); decide → ArmLocal or ArmOrigin on the hub keyed by request UUID.
  2. RunSSE — response stream opens; hub Wait(reqID, 800ms); if local offer present, encode text via RunSSE codec and fulfill; else dial Cursor origin.

Root vs child. Only root Agent RunSSE is a candidate for text-only local fulfill. Child / tool-loop RunSSE (!cursorrpc.IsRootAgentRunSSE) evaluates router.DecideToolFollowup and may emit metric tool_followup_would_local, but Path B tool loops stay on origin by default (opt-in agent_rpc_tool_codec ships a common ToolCall map; full Cursor catalog remains DEFERRED). For Agent+tools, use Path A.

OpenAI-compat bodies intercepted on Path B also call CompleteLocal: local executes; non-local returns ErrOriginPassthrough so the interceptor tunnels to the original Host with Cursor auth intact.

Sticky cloud state machine

Turn-family sticky is not conversation-wide. An explicit flag or a DecideLocal cloud|local decision opens a short-lived family keyed by the root request UUID. Immediate chrome follow-ons (reply summary, title gen) inherit; the next real TipTap user message may re-decide. Implemented on AgentFulfillHub (internal/mitm/agent_fulfill_hub.go).

Bidi decide priority (before DecideLocal)

  1. Explicit /cloud|/heavy → ArmOrigin + OpenTurnFamily(StickyCloud)
  2. Explicit /local|/fast → ArmLocal + OpenTurnFamily(StickyLocal)
  3. ShouldStickyCloudOrigin → origin
  4. Composer wrap-up belt → origin
  5. InheritTurnFollowOn sticky local/cloud
  6. DecideLocal → arm; skip new family for rule composer_wrapup_origin
Why sticky exists. Without it, Composer wrap-ups and title chrome look like small local prompts and steal turns that must stay on the cloud parent that just ran — including after /cloud. See Context and planning/routing_session_policy.md.

Fulfill hub

AgentFulfillHub correlates prompt-side BidiAppend with answer-side RunSSE for the same request UUID. Under sync.Mutex:

  • waiting map[string]chan *AgentFulfillOffer — RunSSE arrived first
  • pending map[string]*AgentFulfillOffer — Bidi arrived first
  • family *turnFamily — {Mode, RootRequestID, Until, Source, ParentActive}

ArmLocal / ArmOrigin call signal: if a waiter exists, send on the buffered channel (size 1); else store pending and schedule expirePending. Wait checks pending, else registers a waiter and selects on offer vs timer; on timeout it re-checks pending for the race where Bidi landed as the timer fired.

Offer payload: Local, extracted CompletionRequest, RoutingDecision, UserText, Source. Local fulfill then runs CompleteLocal and encodes text into RunSSE frames. Encode failure after partial write must not dial origin (client already saw local bytes).

TipTap-safe explicit flags: trailing slash forms and mid-prompt detection so Composer TipTap nodes do not break matching. Classifier tools_force_cloud: true is the default intro posture.

Context graph

Package internal/contextgraph: append-only event log + in-memory turn index for sticky routing and analytics. Persistence under ~/.glider/context/events-YYYY-MM-DD.jsonl. Ring cap context.max_events (default 4096); warm load days default 2; disk retain default 14. Parallel episode rings live in internal/contextkit for local prompt inject — not a full TipTap dump.

Event kinds include:

  • Route / fulfill: RouteDecided, FulfilledLocal, OriginPassthrough, Error
  • Sticky / turn: TurnOpened, StickyBound, RunSSEOpen, RunSSEClose, BidiSeen
  • Agent chrome: SummaryRequested, SubagentSpawned, ToolStarted, ToolFinished

EventLoopStarted/LoopTick/LoopStopped/SwarmFanOut constants still exist in graph.go but nothing currently emits them — dead code left over from the removed hoop/swarm runner, not a live event stream.

APIs used by MITM sticky: BindRequest, BindSession, CloudTurnLive, LiveCloudFamily, TurnIDForRequest / TurnIDForSession. See Context.

Hot-swap & delegation

internal/orchestrator's FanOutExecutor provides bounded multi-backend fan-out (flag-gated, off by default). internal/hotswap.Registry is a separate, general module-registry mechanism bound to config.Provider.Watch: named modules (fan_out, backends, classifier, …) each declare their own Apply; Generation increments on a successful one. Restart-required: MITM CA/hosts/transparent-interception settings, listen ports. Cross-CLI delegation (internal/vendors) is a separate mechanism again — a one-shot headless subprocess per delegate call, not a worker pool or hot-swap module; see planning/permission_relay_design.md.
