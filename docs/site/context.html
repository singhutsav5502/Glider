Memory

Context management

Hybrid dual-layer store: an append-only event log (runtime provenance) plus an entity/edge graph (EXTRACTED | INFERRED | RUNTIME provenance), with an in-memory turn index for sticky routing.

Why

Without a memory layer, Cursor's Composer wrap-ups and subagent chrome look like new small prompts and get mis-routed to local. The graph answers "is this still part of turn family X?" — see MITM · sticky-cloud.

Layers

LayerRolePersist
Event logAppend-only verbs: RouteDecided, FulfilledLocal, OriginPassthrough, TurnOpened, StickyBound, …~/.glider/context/events-*.jsonl
Entity/edge storefile, dir, symbol + relations~/.glider/context/entities.jsonl
EpisodesCompressed session summaries for local prompt injectioncontextkit (in-process rings)

Query

context_query tool / Store.Query search both layers:

context_query: <turn_id> [key=file-tree] [kind=note|file|dir] [prov=RUNTIME|EXTRACTED|INFERRED]
  [neigh=id] [explain=id] [communities=1] keyword…

Explain(id) returns neighborhood + hub/path narrative. DetectCommunities is a connected-component MVP, not full Leiden.

What locals receive

Never the full transcript. A bounded pack: the latest user turn plus up to N compressed episodes (transform.local_context). Dashboard Overview shows episode chips from GET /api/context/episodes.
