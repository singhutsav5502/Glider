Memory

Context management

Hybrid dual-layer store (Graphify methodology): append-only event log (runtime provenance) + entity/edge graph (EXTRACTED | INFERRED | RUNTIME) + in-memory turn index for sticky routing. Durable swarm threads / waves / weave sit beside the graph so wave N+1 can seed from prior outputs without dumping transcripts.

Why

Without a memory layer, Composer wrap-ups and subagents look like new small prompts and get mis-routed to local. The graph answers: "is this still part of turn family X?" Dual-layer Query / context_query also answers structural questions (thread / wave / episode / file) without dumping transcripts.

Dual-layer model

LayerRoleProvenancePersist
Event log Append-only verbs (RouteDecided, SwarmFanOut, LoopTick, EpisodeMerged, FileTreeIndexed, …) Prefer RUNTIME; EXTRACTED when attrs come from tools ~/.glider/context/events-*.jsonl
Entity / edge store thread, wave, worker, episode, file, dir, subtask, conflict + relations (produced, follows, contains, …) EXTRACTED | INFERRED | RUNTIME ~/.glider/context/entities.jsonl
Durable swarm threads Multi-wave FanOut + weave policies; resume after restart RUNTIME writes mirrored into graph ~/.glider/swarm/threads/*.json

Query surface

Store.Query / QueryWith / tool context_query search both layers. Filters:

context_query: <turn_id> [prov=RUNTIME|EXTRACTED|INFERRED] [path=from->to] [neigh=id] [explain=id] [communities=1] keyword…

Examples:
  t-abc wave
  t-abc prov=EXTRACTED readme
  t-abc path=wave-0->wave-1
  t-abc neigh=thr-1-wave-0
  t-abc explain=sym:demo.go#Helper
  t-abc communities=1
  prov=RUNTIME EpisodeMerged

PathSummary(turn, from, to) prefers entity edges, falls back to event scan. Used in production by hoop cycle narratives and multi-wave prompt seeding.

Explain(id) returns neighborhood + hub/path narrative. DetectCommunities is a connected-component MVP (not full Leiden).

Ingest:

  • File-tree: POST /api/context/index-tree or post-git_clone (EXTRACTED dir/file + contains)
  • Symbols: POST /api/context/index-symbols — Go via go/parser, JS/TS/Python via regex; SymbolIndexer interface ready for tree-sitter

Weave (Slate-inspired)

  • Policies — concatenate | role_weighted | critic | conflict_callouts | llm_critic
  • Planner decompose — numbered plan lines become bounded SubTasks for later waves
  • Free spawn — free_spawn: true invents worker roles from [role:] / role= / @role lines (capped ≤4)
  • Resume — GET /api/swarm/threads, POST /api/swarm/threads/{id}/resume
  • Wave timeline — Durable thread View paints Cytoscape wave→worker timeline on the Graph editor
  • Sample — samples/swarms/multi-wave-weave.yaml

Storage

  • Hot — internal/contextgraph.Store keyed by turn_family / request_uuid / connect_session
  • Warm events — JSONL under ~/.glider/context/events-YYYY-MM-DD.jsonl
  • Entities — ~/.glider/context/entities.jsonl
  • Durable swarm threads — ~/.glider/swarm/threads/*.json
  • Episodes — compact outcomes for local prompts (contextkit)

What locals receive

Not the full TipTap mega-dump. Bounded pack: latest user turn + up to N compressed episodes (transform.local_context). Wave N+1 also gets graph-seeded prior_wave + optional PathSummary hint.
