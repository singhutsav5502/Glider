Memory

Context management

Hybrid: append-only event log (runtime provenance) + entity/edge store (Graphify-style structural layer) + in-memory turn index for sticky routing.

Why

Without a memory layer, Composer wrap-ups and subagents look like new small prompts and get mis-routed to local. The graph answers: “is this still part of turn family X?” Dual-layer Query / context_query also answers structural questions (thread / wave / episode) without dumping transcripts.

Storage

  • Hot — internal/contextgraph.Store keyed by turn_family / request_uuid / connect_session
  • Warm events — JSONL under ~/.glider/context/events-YYYY-MM-DD.jsonl
  • Entities — ~/.glider/context/entities.jsonl (threads, waves, workers, edges; provenance EXTRACTED | INFERRED | RUNTIME)
  • Durable swarm threads — ~/.glider/swarm/threads/*.json (multi-wave FanOut + weave)
  • Episodes — compact outcomes for local prompts (contextkit)

What locals receive

Not the full TipTap mega-dump. Bounded pack: latest user turn + up to N compressed episodes (transform.local_context).
