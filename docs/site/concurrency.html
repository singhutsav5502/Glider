Concurrency model

Glider is a long-running Go process with many concurrent clients: Cursor CONNECT sessions, gateway SSE streams, dashboard WebSockets, VRAM pollers, and Loop Engineering runners. This page maps mutexes, channels, and goroutine ownership so operators and contributors can reason about races and backpressure.

Process topology

main
  ├─ gateway HTTP server goroutine(s)     :8080
  ├─ dashboard HTTP + WS                  :8081
  ├─ MITM Accept loop                     :8082
  │    └─ per CONNECT → go handleConn
  ├─ config.Provider.Watch loop
  ├─ VRAM poller (≈5s) via stopVRAM chan
  ├─ backend health poller (≈30s)
  └─ loop runners (on demand, one per hoop id)

Hot path config is mostly atomic.Pointer swaps (Config, router.Engine) so readers avoid long critical sections.

Gateway and MITM may call Handle concurrently for many requests. The completer is designed as mostly immutable wiring + shared dependencies that are themselves synchronized. Do not stash per-request mutable fields on PipelineCompleter.

Loop runners

loop.Manager holds runners map under mu. Start creates a cancelable context derived with context.WithoutCancel from the HTTP request context so returning the REST response does not abort the hoop. Each hoop id has at most one active runner; Stop cancels and waits on a done channel. Stage Completer calls reuse the shared pipeline — same concurrency rules as gateway traffic.

Swarm fan-out

  • Semaphore channel sized to MaxInflight (default 4)
  • Worker WaitGroup + result channel (default sizes 16/32)
  • Parent cancel propagates to workers (errgroup-style Group)
  • Hot-swap Registry Apply under module mutex; generation counter for diagnostics

Dashboard WebSocket

metrics.Bus uses an RWMutex. Subscribers get a buffered channel (Subscribe(32)). Publish is non-blocking: slow WS clients drop events rather than stalling the request path. Each WS connection has a writer goroutine reading from its subscription until disconnect.

Hazards & invariants

  1. Partial local RunSSE write: if encode fails after bytes were written to Cursor, do not dial origin — the client already consumed a response.
  2. Hub timeout vs late Bidi: Wait re-checks pending after timer to avoid dropping a same-millisecond offer.
  3. StickyCloud vs classifier: deny-local happens in MITM before CompleteLocal; do not “fix” sticky by routing small_local inside the pipeline.
  4. WS backpressure: event drops are expected under load; analytics are best-effort, not transactional.
  5. Loop cancel: always use WithoutCancel for hoop lifetime; HTTP handlers must not share request ctx with multi-minute runners.
  6. Blind tunnel: two Copy goroutines + WaitGroup; either direction EOF tears down the CONNECT session.
