Routing

The router evaluates rules in descending priority. Explicit /local / /cloud always win. Token thresholds are a safety net, not the primary "is this simple?" signal.

Priority order (default profile)

PriRuleEffect
100 / 99Explicit /local /fast / /cloud /heavyHard force
95composer_wrapup_originComposer wrap-ups (Cursor MITM) → cloud/origin
~85–70task_classifierTools / must-cloud → cloud; small tasks → local
75Complexity heuristicOpt-in (complexity.enabled)
50Starlark scriptse.g. refactor detect → local
10 / 5Context size>8000 tokens → cloud, else local
0DefaultCloud when unsure (local in the pure-local profile)

A delegate flag (/claude, /cursor-agent, /agy) is claimed before any of this runs — see Delegation.

Cursor MITM turn policy

  • Turn-family sticky — after /cloud (or a cloud DecideLocal decision), reply-summary/title/mid-turn subagents stay origin for a TTL + parent-run grace.
  • Deny-local for non-fresh-user follow-ons while sticky is live.
  • Next real user message can re-decide (may go local again).
  • Tool follow-up — child tool calls re-evaluate allow/deny.

This mechanism is specific to Cursor's own MITM protocol — detail in MITM. Full policy: planning/routing_and_context.md.
