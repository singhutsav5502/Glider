C4 model · Level 1

System context

Glider is a local-first AI harness that sits beside Cursor. It is not a fork of Cursor and not a replacement IDE. It intercepts or receives model traffic, routes simple work to local GPUs (Ollama / vLLM), and falls back to BYOK cloud APIs or Cursor origin depending on path. Authority for status: planning/README.md (skip planning/Depreceated/).

Step-by-step tech (context level)

  1. Operator starts Glider cmd/glider/main.go · config.LoadConfig · slog · signal.Notify Loads YAML (default configs/glider.yaml), builds one shared PipelineCompleter, starts listeners.
  2. Cursor sends traffic Path A: HTTP JSON to :8080/v1 · Path B: HTTP CONNECT to :8082 Chat/Ask/Agent either hit the OpenAI-compat gateway or the MITM forward proxy.
  3. Glider decides local vs not internal/router.Engine · mitm.AgentFulfillHub sticky (Path B) Explicit flags, sticky turn family, classifier, Starlark, token ceiling, default.
  4. Execute or passthrough Ollama/vLLM HTTP · cloud SDK · or blind/origin tunnel to Cursor Local GPUs for simple turns; BYOK or Cursor origin otherwise.
  5. Persist operator telemetry ~/.glider/history · ~/.glider/context · dashboard :8081 Metrics bus, contextgraph events, optional episode ring.

Dual mode at context level

ModeCursor settingGlider surfaceNon-local means
A -- Gateway Override Base URL → http://127.0.0.1:8080/v1 Gateway container Your OpenAI/Anthropic keys
B -- MITM http.proxy → :8082 + trust Glider CA MITM container Cursor origin (subscription)

Both modes share one harness. Path B Agent tools still prefer origin today; for Agent+tools use Path A with cus- / glider- model IDs.
